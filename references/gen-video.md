# 视频提示词（gen-video）

> 整合自 [q253595422/prompt-constraints](https://github.com/q253595422/prompt-constraints)（MIT）。前置阅读：`gen-core.md`（六层约束）。

## 一、视频与生图的根本差异

| 维度 | 生图 | 视频 |
|---|---|---|
| 时间 | 单帧静态 | **时序**，动作按时间展开 |
| 重心 | 构图 / 光影 / 材质 | **运动 / 镜头 / 表演 / 声音** |
| 一致性 | 一张图内部 | **跨帧、跨镜**自洽 |
| 参数 | 比例 | 比例 + **时长** + 镜头数 |
| 冗余 | 描述画面一切 | 描述**变化**，静态越少越好 |

**核心约束：视频提示词描述「运动和变化」，不是描述画面长什么样。** 首帧已说清的不重复。

## 二、全局视频约束（T1—T6）

- **T1 参数不进正文**：模型名、时长、比例、分辨率单独列「推荐参数」行；例外是官方 schema 本身要求（MiniMax 字段、Seedance 多镜头时间轴）。
- **T2 时长只用于内部规划**：时长决定能承载几个动作节拍，不写进正文。
- **T3 图生视频时图是视觉锚点**：不深描述图片内容，只写运动、镜头、表演、声音。
- **T4 动作连续性**：明确「连续 / 一镜到底 / 无剪辑」，排除跳切、瞬移。
- **T5 物理可信**：加速度、惯性、遮挡、因果必须成立，写清「谁导致什么」。
- **T6 单镜头动作密度受限**：短片段塞太多节拍 = 全都做不好，宁可少而清晰。

## 三、输入模式判定

| 模式 | 提示词重心 |
|---|---|
| 文生视频 t2v | 一切都写：主体、动作、环境、镜头、声音 |
| 图生视频 i2v | 只写变化：运动、镜头、表演、声音 |
| 首尾帧控制 | 写清「从哪到哪」的转场/运镜/关键节拍 |
| 参考驱动（多图/视频/音频） | **逐资产声明角色**（见下） |
| 编辑 / 续写 | 写清什么保留、什么改变、从哪续 |

多资产场景逐个声明职责，不让模型猜：`参考图 1 的构图与分镜，使用图 2 的角色、图 3 的场景，运动节奏对齐视频 1，氛围参考音频 1`。

## 四、结构与五段式

组织顺序：输入用法 → 规格（比例、时长、单镜/多镜）→ 视角与运动 → 节拍顺序 → 紧凑时间轴 → 环境动态与声音（有用才写）→ 一致性声明 + 回避清单。

五段式速记（Veo 系官方口径，通用性好）：

```
[电影摄影] + [主体] + [动作] + [上下文/环境] + [风格与氛围]
```

## 五、时间轴容量表

节拍数由时长决定，超出容量就建议缩短时长或拆镜头：

| 时长 | 建议节拍 | 目标/人物数 | 处理 |
|---|---|---|---|
| 5—8s | 1—2 | 1—3 | 一个清晰动作，一次变化 |
| 8—12s | 2—3 | 3—4 | 短互动 + 一次揭示 |
| 12—15s | 3—4 | 4—5 | 顺序停靠的理想区间 |
| 15—25s | 4—6 | 5—8 | 节拍变短，分组过渡 |
| 25s+ | 拆镜头 | 8+ | 分组 / 分区 / 多镜头 |

时间轴模板：

```
0.00—X.Xs：<建立起点与环境动态>
X.X—X.Xs：<节拍 2：移动到目标，动作/反应>
X.X—ENDs：<收束或回望全景>
```

无时间戳时用「先…接着…随后…最后…」叙事顺序，或 `Shot 1 / Shot 2 / Final shot` 分段。

## 六、POV 与物理约束

FPV 不等于人眼高度；用户指定就遵从，没指定则选让场景更成立的视角。**必须强制物理限制**：

| POV 身份 | 物理约束 |
|---|---|
| 人 | 眼高、步行起伏、呼吸感、手/衣袖可入画 |
| 猫狗 | 低高度、好奇转头、爪/尾可入画、**无人类手势** |
| 无人机 | 平滑连续飞行、高度变化、倾斜转弯、**无步行起伏** |
| 扫地机器人 | 极低高度贴地滑行、家具腿显大、**不能上沙发/跳/爬楼梯** |
| 鸟/虫/灵体 | 漂浮弧线或滑翔，连续且动机合理 |

> 猫不能飘过桌子；无人机不能穿墙；扫地机器人不能跳上沙发。

## 七、路径控制 vs 编号停靠（选错毁掉整条视频）

**编号停靠（近景互动默认优先）**：室内、角色互动、需要精确目标数量的场景。首帧图规则：不画红色路线/箭头；目标旁放小号编号标记，按**空间可达深度**从近到远排列；每下一站必须物理可达；先设计可行进路线，再摆角色。

**红线路径控制**：航拍地图、城市飞越、赛道线等大尺度场景。路线图用 16:9 高分辨率地图 + **一条**连续红线；视频 prompt 必须声明「上传图是路线规划图不是最终画面，红线/标注必须完全消失」；按**地理分段**推进（平静起点→过渡→地标→危险区→终点，4—6 个可区分路段）；POV 用隐形第一人称（无人机/鸟/灵体）。

## 八、音频导演（支持音频的模型）

- 台词用引号包住准确内容：`一位女性说："我们必须现在离开。"`
- 音效显式点名：`音效：远处雷声炸裂。` 环境声定义声场：`环境声：舰桥低沉的嗡鸣。`
- 不要台词就直接说明，只写音效/环境声；声音对齐画面节拍，不写对不上的音轨。

## 九、镜头语言

用标准电影动词，不自造词：缓推 slow push-in ｜ 跟拍 tracking shot ｜ 摇臂 crane shot ｜ 航拍 aerial view ｜ 缓摇 slow pan ｜ 环绕 orbit ｜ 第一人称 POV shot ｜ 甩镜 whip pan ｜ 升降 boom up/down ｜ 变焦推拉 dolly zoom；景别：wide shot / close-up / extreme close-up / medium shot / two-shot / low angle；焦点：shallow depth of field / deep focus / macro。连续运动描述：持续前推、自然倾斜、近距离掠过、高度变化、前景视差、渐进加速、地平线稳定。

## 十、视频常见失败模式

| 症状 | 根因 | 修法 |
|---|---|---|
| 像一张会动的图 | 只描述了静态画面 | 改写成运动/镜头/表演/声音 |
| 动作做不出来/中途变形 | 节拍超出时长容量 | 减节拍或加时长 |
| 画面出现数字/箭头/UI | 未声明「标记只是参考不得入画」 | 补显式排除 |
| 角色第二镜换脸 | 缺一致性声明 | 补不变量 + 角色参考图（见 `gen-consistency-negative.md`） |
| 路径穿过障碍物 | 路线未按可达性设计 | 先画可行路线，再放目标 |
| 猫飘起来 / 无人机走路 | POV 物理约束缺失 | 按 §六 补约束 |
| 提示词混了工具参数 | 参数未外置 | 按 T1 剥离到「推荐参数」行 |
| 音画不同步 | 声音未对齐节拍 | 音频线索绑到时间轴节点 |
